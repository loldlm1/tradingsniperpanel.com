# Database Model Reference
Short, API-flavored map of the persisted data model so agents and developers can reason about queries and payloads without digging through migrations.

## Domain map
- Users authenticate via Devise and can originate from OAuth (`provider`, `uid`, `oauth_data`). `role` enum: `trader`, `partner`, `admin`, `master_admin`.
- ExpertAdvisors describe each EA/tool/indicator/script (`ea_type`, `doc_guide_en/es`, `ea_files` attachment, `allowed_subscription_tiers`, `trial_enabled`); referenced by Licenses and UserExpertAdvisors.
- ExpertAdvisorBundles map an EA plus a sorted add-on key set to a downloadable bundle file for base/combination binaries.
- Courses provide premium learning content with localized titles/descriptions, module/lesson structure, and Stream-backed videos; entitlements connect Courses to BillingPlans for tier access, with enrollments tracking user progress.
- BillingPlans retain current and historical subscription/one-time catalog rows. The active purchasable subscription catalog contains Chu Sniper Trailing monthly (`1999` USD cents) and annual (`15592` USD cents, 35% below twelve monthly periods), plus the unchanged Pandora Box EA monthly (`7900` USD cents) and annual (`61620` USD cents). BillingPlanPrices preserve current and retired Stripe price mappings. BillingPlanEntitlements connect Chu plans to Chu and Pandora plans to Pandora plus Chu.
- MarketplaceAssets store downloadable marketplace content (PDF guides, templates) with localized titles/descriptions and a file attachment; access is enforced via marketplace purchases only (subscription entitlements are stored but not used for access).
- Tags (acts-as-taggable-on) power Marketplace filtering across ExpertAdvisors, Courses, and MarketplaceAssets.
- Licenses tie a User to an ExpertAdvisor with status (`trial`, `active`, `expired`, `revoked`), expiry fields, an `encrypted_key`, positive `token_version`, and `token_rotated_at`. BrokerAccounts hang off Licenses and record daily PnL snapshots.
- LicenseOnlineSessions track active EA connections for seat enforcement by `user + EA + broker identity` with an entitlement source (`subscription` or `one_time`) and `last_seen_at` heartbeat timestamp.
- LicenseLaneMagicNumbers persist lane-scoped backend `magic_number` values keyed by `source + email + license/ea + broker identity` so verify and daily-results remain consistent per lane.
- LicenseInstanceMagicNumbers persist chart-instance-scoped backend `magic_number` values keyed by `broker account + EA + instance_id` so upgraded EAs can use per-chart trade ownership without changing lane entitlement behavior.
- UserExpertAdvisors is a soft-deletable join for entitlement tracking (`subscription_tier`, `pay_subscription_id`, `expires_at`, `deleted_at`).
- Referrals via the `refer` gem: referral_codes/visits/referrals tables connect referrers/referees; PartnerProfile leverages this.
- Partner program: PartnerProfile (one per partner User) → PartnerMembership (downline users, with `depth` and optional `referral_id`) → PartnerCommission rows (per charge/subscription, status, amounts, `commission_kind`) → optional PartnerPayoutRequest.
- Manual billing: ManualTransactions retain historical one-time off-Stripe purchases. ManualSubscriptions grant fixed Pandora periods with `granted_days`, payment status, recorder, and Stripe supersession fields; an active Stripe subscription blocks a new grant and later paid Stripe access supersedes remaining manual access. RevenueSplitRule stores global profit split percentages for admin analytics.
- DiscordConnections store one optional Discord identity per User, safe display fields, membership-screening state, VIP role state, sync lease/status, timestamps, and stable error codes. A partial unique index enforces one Rails owner per non-null Discord identity; OAuth tokens and raw provider payloads are never stored.
- AdminAuditEvents record idempotent manual grants, manual revocations, and user/global token rotations with safe metadata only. They never store current/prior tokens, decrypted payloads, raw Stripe objects, or secrets.
- Billing (Stripe via Pay gem): Pay::Customer, Pay::Subscription, Pay::Charge, Pay::PaymentMethod, Pay::Webhook keep processor state; `customer.owner_type` is `User`.

## Tables and key fields
- `users`: `email` (uniq), `encrypted_password`, `name`, `preferred_locale`, `time_zone`, `provider`/`uid`, `oauth_data` JSON, `terms_accepted_at`, `role` enum. Associations: `pay_customers`, `licenses`, `user_expert_advisors`, `partner_profile`, refer gem (`referrer`, `referral_codes`, `referrals`).
- `expert_advisors`: `name`, `description`, `ea_type` enum (`ea_robot`, `ea_tool`, `indicator`, `script`), `doc_guide_en`/`doc_guide_es` (markdown text), `allowed_subscription_tiers` JSON array, `ea_id` (immutable slug/id), `trial_enabled`, `deleted_at`, `ea_files` (Active Storage attachment for the EA bundle).
- `courses`: `slug`, `status` (`draft`, `published`), `category`, `position`, `published_at`, localized `title_*`, `summary_*`, `description_*`, `cover_image` (Active Storage); has many `course_modules`, `course_lessons`, and entitlements to billing plans.
- `course_modules`: `course_id`, `position`, localized `title_*`, `summary_*`; has many `course_lessons`.
- `course_lessons`: `course_module_id`, `position`, localized `title_*`, `summary_*`, `body_markdown_*`, `stream_uid`, `duration_seconds`.
- `course_plan_entitlements`: `course_id`, `billing_plan_id` (unique per pair) connecting paid tiers to courses.
- `marketplace_assets`: `slug`, `status` (`draft`, `active`), `sort_order`, localized `title_*`, `summary_*`, `description_markdown_*`, `file` attachment.
- `asset_plan_entitlements`: `billing_plan_id`, `marketplace_asset_id` (unique per pair) connecting plans to marketplace assets.
- `course_enrollments`: `user_id`, `course_id`, `progress_percent`, `started_at`, `completed_at`, `last_lesson_id`.
- `course_lesson_progresses`: `user_id`, `course_lesson_id`, `status` (`started`, `completed`), `progress_seconds`, `completed_at`, `last_watched_at`.
- `billing_plans`: `key` (uniq), `name` (uniq), `kind` (`subscription`, `one_time`), `tier`, `interval`, `interval_count`, `amount_cents`, `currency`, `stripe_product_id`, `stripe_price_id` (uniq), `active`, `sort_order`, `metadata`. Historical kinds/rows remain queryable; only the four complete Chu/Pandora subscription keys are active/purchasable.
- `billing_plan_prices`: `billing_plan_id`, `stripe_price_id` (uniq), `amount_cents`, `currency`, optional `interval`/`interval_count`, `active`, `current`, `retired_at`, `metadata`. One current row per plan; retired mappings remain available for invoice labels, audits, legacy-subscription interval resolution, and rollback planning.
- `billing_plan_entitlements`: `billing_plan_id`, `expert_advisor_id`, timestamps. Unique `billing_plan_id + expert_advisor_id`.
- `addons`: `key` (uniq), `billing_plan_id` (uniq), `addonable_type/id` (ExpertAdvisor/Course/MarketplaceAsset), `metadata` JSON. One add-on per BillingPlan; EA/Course add-ons allow subscription or one-time base access, MarketplaceAsset add-ons require a base marketplace purchase.
- `expert_advisor_bundles`: `expert_advisor_id`, `bundle_key` (sorted add-on key set), `required_addon_keys` (CSV), `active`, `sort_order`, `bundle_file` attachment. One bundle per key set.
- `licenses`: `user_id`, `expert_advisor_id`, `status` (`trial`, `active`, `expired`, `revoked`), `plan_interval`, `expires_at`, `trial_ends_at`, `encrypted_key`, `token_version` (positive, default `1`), `token_rotated_at`, `source`, `access_source`, `last_synced_at`. Unique `user_id + expert_advisor_id`. Scopes: `active_or_trial`.
- `license_online_sessions`: `user_id`, `expert_advisor_id`, `company`, `account_number`, `account_type` (`real`, `demo`), `entitlement_source` (`subscription`, `one_time`), `last_seen_at`. Unique identity: `user_id + expert_advisor_id + company + account_number + account_type`.
- `license_lane_magic_numbers`: `license_id`, `source`, `email`, `company`, `account_number`, `account_type`, `magic_number`. Unique lane key: `license_id + source + email + company + account_number + account_type`; `magic_number` is globally unique and constrained to signed-32-bit-safe positive values.
- `license_instance_magic_numbers`: `license_id`, `broker_account_id`, `expert_advisor_id`, `source`, `email`, `instance_id`, `magic_number`, `first_seen_at`, `last_seen_at`. Unique instance key: `broker_account_id + expert_advisor_id + instance_id`; unique trade magic: `broker_account_id + magic_number`; `instance_id` is max 64 ASCII characters (`A-Z`, `a-z`, `0-9`, `_`, `-`); `magic_number` is constrained to signed-32-bit-safe positive values.
- `broker_accounts`: `license_id`, `company`, `account_number`, `account_type` enum (`real`, `demo`), optional `name`. Uniqueness: `company + account_number + account_type`.
- `broker_account_daily_results`: `broker_account_id`, `expert_advisor_id`, `magic_number`, `result_timestamp` (unix seconds), `result_value` (decimal). Uniqueness: one result per UTC day for `broker_account + expert_advisor + magic_number`; new writes expect the same signed-32-bit-safe range used by lane and instance allocation.
- `user_expert_advisors`: `user_id`, `expert_advisor_id`, `subscription_tier`, `pay_subscription_id`, `expires_at`, `deleted_at`. Default scope filters `deleted_at`; scope `active` filters out expired/soft-deleted.
- `partner_profiles`: `user_id` (uniq), `discount_percent`, `payout_mode` enum (`once_paid`, `concurrent`), `stripe_coupon_id`, `active`, `started_at`. Scope: `active`.
- `partner_memberships`: `partner_profile_id`, `user_id` (one active at a time), optional `referral_id`, `depth`, `started_at`, `ended_at`. Scope: `active`.
- `partner_commissions`: `partner_profile_id`, `partner_membership_id`, `referred_user_id`, optional `referral_id`, `pay_charge_id`, `pay_subscription_id`, `payout_request_id`, `commission_kind` enum (`initial`, `renewal`), `status` enum (`pending`, `requested`, `paid`, `cancelled`), `amount_cents`, `currency`, `percent_applied`, `occurred_at`, `metadata` JSON. Scope: `pending_or_requested`.
- `partner_payout_requests`: `partner_profile_id`, `status` enum (`pending`, `paid`, `cancelled`), `total_cents`, `requested_at`, `paid_at`, `payment_reference`, `note`.
- `manual_transactions`: `user_id`, `billing_plan_id`, `amount_cents`, `currency`, `paid_at`, `payment_method`, `reference`, `recorded_by_admin_id`, `notes`. One-time only; unique `user_id + billing_plan_id`.
- `manual_subscriptions`: `user_id`, `billing_plan_id`, `granted_days`, `amount_cents`, `currency`, `payment_status` (`complimentary`, `pending`, `paid`), `paid_at`, `starts_at`, `ends_at`, `status` (`active`, `expired`, `cancelled`, `superseded`), `superseded_at`, `superseded_by_pay_subscription_id`, `payment_method`, `reference`, `recorded_by_admin_id`, `notes`.
- `discord_connections`: unique `user_id`, nullable partially unique `discord_user_id`, safe `discord_username`/`discord_global_name`, `linked_at`, unlink/disconnect timestamps, nullable `membership_pending`, `vip_role_state` (`unknown`, `pending`, `granted`, `removed`), `sync_status` (`idle`, `queued`, `syncing`, `failed`), short sync lease, last-sync timestamp, and stable error code/time. Identity/link coherence is enforced by a database check constraint.
- `admin_audit_events`: `actor_id`, optional polymorphic `target`, `action` (`manual_subscription.granted`, `manual_subscription.revoked`, `licenses.subscription_rotated`, `licenses.all_rotated`), unique `request_id`, JSON `metadata`, timestamps. Target is a User for manual/user operations and blank for global rotation.
- `revenue_split_rules`: `effective_at`, `us_percent`, `client_percent`, optional `note`.
- `refer_referral_codes`: `referrer_type/id`, `code` (uniq), counters; `refer_referrals`: `referrer_type/id`, `referee_type/id`, optional `referral_code_id`, `completed_at`; `refer_visits`: `referral_code_id`, `ip`, `user_agent`, `referrer`, `referring_domain`.
- Pay tables (from `pay` gem): `pay_customers` (owner polymorphic, `processor`, `processor_id`, `default`, `data`), `pay_subscriptions` (status, current/trial periods, `processor_plan`, `ends_at`, `metadata`), `pay_charges` (amount, currency, `processor_id`, `subscription_id`, `application_fee_amount`, `metadata`), `pay_payment_methods`, `pay_merchants`, `pay_webhooks`. Catalog migration metadata stores only safe target plan/price, schedule ID, migration key, and effective/scheduled timestamps.
- Tag tables (acts-as-taggable-on): `tags` (`name`, `taggings_count`), `taggings` (`tag_id`, `taggable_type/id`, `context`, `tagger_type/id`, `tenant`).

## Common queries and services
- License access map: `Licenses::AccessibleExpertAdvisors` preloads `ExpertAdvisor.active.includes(:licenses)` and the user’s licenses/broker_accounts, returning per-EA entries with status, key, expiry, and allowed tiers.
- License verification API: `Licenses::LicenseVerifier` checks source, user/email, EA, license record, status, secure compares `encrypted_key`, and validates with `LicenseKeyEncoder`.
- Lane magic assignment: `Licenses::LaneMagicNumberAllocator` creates/reuses signed-32-bit-safe random lane `magic_number` values for `licenses/verify` and lazily remaps oversized legacy lane rows on successful verify.
- Instance magic assignment: `Licenses::InstanceMagicNumberAllocator` creates/reuses signed-32-bit-safe random instance `magic_number` values for `licenses/instance_magic`, keeps magic unique per broker account, avoids colliding with legacy lane magic for the same broker identity, and logs only a hashed/truncated `instance_id` fingerprint.
- Add-on gating: `Addons::Eligibility` validates paid base access before one-time add-on purchases; `Licenses::AddonAccess` checks add-on ownership during `licenses/verify`.
- Marketplace access: `Marketplace::Catalog` builds entries with tags/entitlements; `Marketplace::AssetAccess` validates asset access via marketplace purchases (one-time only).
- Billing setup: `Billing::PlanCreator` creates/reuses one Stripe product per catalog product and exact prices while preserving local price history. `Billing::SubscriptionCatalogReconciler` (with the `Billing::PandoraCatalogReconciler` compatibility facade) verifies desired state, schedules legacy Pandora renewals before retirement, retires stale purchase/access paths, and verifies final state; `Catalog::RetireLegacyAccess` preserves financial history while disabling access.
- Renewal migration: `Billing::LegacySubscriptionMigrator` maps monthly/yearly legacy Pay subscriptions to the matching Pandora plan at `current_period_end`; `Billing::StripeSubscriptionSchedule` preserves current quantity/phase, rejects unmanaged schedules, and uses safe metadata plus idempotency for retry recovery.
- Subscription sync: `Licenses::SubscriptionLicenseSync` resolves tier/interval through current or historical Stripe price mappings, generates/updates Pandora licenses, supersedes active manual grants when Stripe wins, marks referral completed, and expires disallowed licenses.
- Manual access: `ManualSubscriptions::Grant` accepts only a purchasable Chu/Pandora subscription plan and `1..730` days, extends from the later of now/current manual end, normalizes complimentary/pending/paid audit fields, rejects active Stripe access, and creates an idempotent AdminAuditEvent. `ManualSubscriptions::Revoke` cancels active or future manual access immediately, preserves the original period, and records the operator and revocation time atomically.
- Token rotation: `Licenses::RotateTokens` atomically increments versions and replaces exact stored keys. Admin/master-admin may rotate one user's active/trial subscription licenses; only master-admin may rotate all active/trial licenses. Prior tokens fail exact secure comparison immediately and are not retained. The authenticated EA pages are non-cacheable, render the complete current key plus token version/rotation time, and copy the full value rather than its visually shortened prefix.
- Subscription renewal: Pay subscription updates enqueue `Licenses::SyncSubscriptionJob`; advancing `current_period_end` reissues that user's subscription keys with the new expiration while preserving the current token version and admin rotation timestamp. The previously stored exact key becomes invalid, but renewal is not recorded as an admin token-version rotation.
- Discord VIP: `Discord::VipEligibility` reuses the authoritative active-subscription finder, plan resolver, and paid-status rules. `Discord::LinkAccount` performs one-time OAuth identity/guild joining without token persistence. `Discord::SyncVipRole` uses a retry-safe lease and changes only the configured VIP role; Pay/manual callbacks enqueue event sync and `Discord::ReconcileVipRolesJob` repairs linked rows hourly. Safe unlink retains identity until removal succeeds.
- Admin subscription audit: `Admin::SubscriptionAudits::Query`, `Presenter`, and `InvoiceSnapshot` combine Pay, manual, price-history, discount/promotion, refund, period, entitlement, license-version, and audit-event data without exposing license keys or raw Stripe payloads.
- Trial provisioning: `Licenses::TrialProvisioner` (via `Licenses::CreateTrialLicensesJob`) issues `trial` licenses for trial-enabled EAs when keys are configured.
- Referrals: `Referrals::AttachReferrer` links a user by referral code, ensures their own code, and assigns partner membership; `Referrals::MarkCompleted` marks referral complete on successful subscription.
- Partner program: `Partners::MembershipManager` ensures partner profiles for partners, assigns memberships based on nearest upstream partner (with `depth`), and reassigns descendants via job. `Partners::CommissionBuilder` builds commissions from Pay charges (looks up net via Stripe, enforces once vs renewals). `Partners::PayoutRequestor` batches pending commissions into a payout request and marks them `requested`.
- Dashboard queries: `DashboardsController` pulls the latest active Pay subscription and last 20 charges; `Dashboard::PartnerController` searches memberships by user name/email (`ILIKE`), loads commissions with includes, aggregates sums for metrics, and counts active subscribers via `Pay::Subscription` join on owner IDs.
- API rate limit: `Api::V1::LicensesController#verify` caches per-email hits (60/min) and upserts BrokerAccounts (retrying on uniqueness conflicts).

## API surface
- License token compatibility is internal to `license_key`: v1 decrypts to `email,ea_id,expires_at`; v2+ decrypts to `email,ea_id,expires_at,token_version` with a positive integer fourth field. Rotation changes the exact stored key/version, but no endpoint adds a token-version request or response field and the JSON/error contracts below remain unchanged.
- `POST /api/v1/licenses/verify` (JSON only): params `source`, `email`, `ea_id`, `license_key`, optional `addons` (comma-separated add-on keys), required `broker_account` payload (`name`, `company`, `account_number`, `account_type`). Success returns `ok`, `plan_interval`, `trial`, `expires_at` (unix timestamp), required signed-32-bit-safe `magic_number`, `granted_addons`, and optional `broker_account`. Oversized legacy lane rows are lazily remapped on successful verify. Errors: `invalid_source`, `invalid_payload`, `user_not_found`, `ea_not_found`, `license_not_found`, `invalid_key`, `expired`, `trial_disabled`, `addons_required` (`required_addons`/`missing_addons`), `online_limit_reached`, `rate_limited`, `internal_error`.
- `POST /api/v1/licenses/heartbeat` (JSON only): params `source`, `email`, `ea_id`, `license_key`, required `broker_account` (`company`, `account_number`, `account_type`, optional `name`). Success refreshes online lease and returns `ok`, `plan_interval`, `trial`, `expires_at`, and optional `broker_account` (no `magic_number` rotation/reissue). Errors mirror verify (minus add-on validation and verify-only magic assignment).
- `POST /api/v1/licenses/instance_magic` (JSON only): params `source`, `email`, `ea_id`, `license_key`, required `broker_account` (`company`, `account_number`, `account_type`), and required `instance_id`. Purpose: validate license identity and broker context, require an existing active lane session without mutating online seats, and allocate or return stable per-chart trade magic. Success returns `ok`, `instance_id`, required signed-32-bit-safe `magic_number`, and `trade_identity_scope: "instance"`. Same license + broker account + EA + `instance_id` returns the same `magic_number`; different instance IDs on the same broker account do not collide numerically, including across different EA IDs. Errors: `invalid_source`, `invalid_payload`, `missing_instance_id`, `invalid_instance_id`, `user_not_found`, `ea_not_found`, `license_not_found`, `broker_account_not_found`, `invalid_key`, `expired`, `trial_disabled`, `lane_session_required`, `rate_limited`, and `internal_error`.
- `POST /api/v1/broker_accounts/daily_results` (JSON only): params `source`, `email`, `ea_id`, `license_key`, `broker_account` (`company`, `account_number`, `account_type`), required signed-32-bit-safe `magic_number`, `result_timestamp` (unix seconds), `result_value`. `magic_number` may be legacy lane magic from `licenses/verify` or instance magic from `licenses/instance_magic`. Success returns `ok`, `broker_account_id`, `result_on` (`YYYY-MM-DD`), and `result_value`. Errors include `missing_magic_number`, `invalid_magic_number`, `broker_account_not_found`, `already_recorded`, `invalid_payload`, `invalid_key`, `invalid_source`, and `internal_error`.

## Data flow highlights
- New user: Devise creates the account and referral records; roles authorize account/admin workflows but do not grant product access. Trial provisioning may enqueue, but only active trial-enabled catalog EAs can receive a trial.
- Checkout/upgrade: `DashboardsController#checkout` accepts only complete active Chu/Pandora monthly/annual keys, applies referral discount (via `Billing::ApplyReferralDiscount` + `Partners::DiscountResolver`/coupon), and redirects to Stripe Checkout; webhooks or subscription sync keep licenses aligned. When Discord automation is enabled, only the Checkout success destination changes to the localized Discord activation page; its query string is presentation-only and cannot grant entitlement or a role.
- Deploy reconciliation: `db:seed` creates/verifies the complete Chu/Pandora catalog and schedules legacy Pandora renewals before stale catalog/access retirement. `catalog:subscriptions:verify` is authoritative and `catalog:pandora:verify` remains a compatibility alias for the existing setup hook.
- Manual grant: ActiveAdmin creates an auditable fixed Pandora period; asynchronous license sync cannot overwrite a newer paid Stripe entitlement and instead marks the manual period superseded.
- Partner payouts: partners request payouts via `Dashboard::PartnerController#request_payout`, which groups pending commissions and marks them requested; `PartnerPayoutRequest#mark_paid!/mark_cancelled!` transition state and update related commissions.
